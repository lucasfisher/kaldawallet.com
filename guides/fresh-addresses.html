Fresh addresses

A different address for each person, so your payments can't be lined up.

Simple

On Bitcoin and some other coins, anyone can look up an address and see every payment it has ever received. If everyone pays you at the same address, they can all see each other's payments.

So each contact you share with gets their own address, like giving each friend a different letterbox. On the Receive screen, New address makes a fresh one whenever you like, for example for a one-off payment.

You don't need to do anything else. Old addresses keep working, everything adds up to one balance, and your recovery phrase brings them all back. Profile → Backup & security → My keys lists every address with what it holds.

This works on Bitcoin, Litecoin, Dogecoin, Bitcoin Cash and Monero. Tip: sending everything at once (Max) combines all your coins in one payment, which shows they belong together.

Detailed

Coins that work like cash

Bitcoin, Litecoin, Dogecoin and Bitcoin Cash use the UTXO model: your balance is a collection of separate coins (unspent transaction outputs), each locked to an address. A wallet can use as many addresses as it likes, and the network treats them all alike.

Account-based networks such as Ethereum, the XRP Ledger and Solana work differently: one address holds one running balance, so a fresh address would be a separate account. On Ethereum, BNB Chain, Avalanche and Polygon, stealth addresses give the same benefit.

One phrase, endless addresses

Hierarchical deterministic (HD) wallets, an open standard most wallets share, turn one recovery phrase into a numbered sequence of addresses. Restoring the phrase recreates the same sequence. Wallets find used addresses by checking them in order until they meet a run of unused ones, a convention known as the gap limit.

Monero subaddresses

Monero is already private on-chain, but its subaddresses let you give different people different addresses for one wallet, so two people can't compare notes and discover they're paying the same person.

In depth

Why address reuse leaks

Public blockchains form a transaction graph: every coin points back to the coins that created it. Analysts cluster addresses into wallets using heuristics, and reusing one address puts every payment to it in the same cluster at once.

Common-input ownership

A transaction that spends several coins needs a valid signature for each, so observers assume all its inputs belong to one owner. This common-input-ownership heuristic is the strongest clustering rule, and it's why combining coins from many addresses in one payment, or sweeping everything, links them.

Change detection

Most payments create change: an output back to the sender. Analysts guess which output is change from clues such as round amounts, address type or how it is later spent, and so follow the sender's money forward.

Deterministic key derivation

HD wallets derive each child key from a keyed hash (HMAC-SHA512) of a parent key and an index. The results look random to anyone without the parent key, so addresses from one phrase can't be linked just by looking at them, yet the owner can regenerate every one from the phrase.

Addresses from keys

An address is a hash of a public key (or of a script), so a fresh key gives an unrelated-looking address at no cost. Encodings such as Base58Check and Bech32 add a checksum, so typing mistakes are caught before any money moves.
